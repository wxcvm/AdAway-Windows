# 监听地址与更新方式

设置页分别输入本机 IPv4 / IPv6，支持同时启用；留空关闭对应协议，不能全部关闭。“仅本机（推荐）”填写 127.0.0.1 / ::1，“所有网卡”按钮填写 0.0.0.0 / ::。旧单 IP / bind_all 配置在重新保存监听设置前保留原有含义。
输入停止约 600 毫秒后自动检测，也可点击检测按钮。检查 HTTP、HTTPS 端口范围、重复与管理端口冲突、本机地址、系统保留端口，以及 IPv4 / IPv6 TCP 监听进程。
当前进程占用会单独显示 PID，允许保存并重启；其他进程占用或检测失败会阻止保存。启用“随服务器启动创建缺失地址”时，缺失且支持创建的私有地址允许保存，直到实际启动才请求创建授权；具体行为见 [监听生命周期](listener-lifecycle.md)。
检测只是当时的状态，重启前其他程序仍可能抢占端口；启动结果以概览的真实监听表为准。
管理接口保持回环地址。指定自定义 IP 时不再暗中增加 127.0.0.1 的 80/443 兼容监听。
配置写入使用同目录暂存、刷新和原子替换；失败保留旧文件。快捷方式和重启入口读取保存的设置。
备用端口按钮只填入草稿并检测，不再未经检查保存并强制重启。

原“用便携包更新”按钮实际只是持久化 `update_mode=portable` 并检查新版本，名称容易误解。
现在“更新方式”可在自动与 ZIP 覆盖间切换，显示当前状态，保存失败有反馈；点击“检查更新”才开始检查。
自动模式优先安装器，安装器无法启动时下载同一版本的 ZIP 并原地替换。
ZIP 模式直接选 ZIP，避免先下载安装器再下载 ZIP。两者都要求有新版本与正确 SHA-256；不会强制重装当前版本。
预览发行使用同一安装标识；它不推进稳定更新源。

维护按钮也按真实行为显示：原“清空统计”实际执行磁盘保存，现名为“立即保存统计”；它不会清零。
控制命令现在读取完整 HTTP 响应头和状态码，不再把 socket 发送成功当成操作成功。
订阅重载、策略加载和 CA 轮换会显示服务端拒绝或未确认的状态。完成 CA 文件轮换不会自动移除 Windows 信任库中的旧证书。

验收范围：CI 真实套接字占用检测、native 输入验证、主程序自定义地址启动、GUI 控件操作、完整 Windows 构建。
日常主机的网络接管和真实设备恢复仍需单独验收。

## 创建缺失的本机地址

“创建 IPv4…”/“创建 IPv6…”会先显示对应目标 IP、软件回环接口、/32 或 /128、管理员授权和有效期，再通过系统 UAC 请求授权。
仅支持私有 IPv4（RFC 1918 或 127/8）及 IPv6 ULA（fc00::/7）；公网、链路本地、多播、映射 IPv4、通配地址不自动创建。
已有地址直接复用，不取得所有权。新地址只加到 IF_TYPE_SOFTWARE_LOOPBACK，使用 SkipAsSource，保持物理网卡、DHCP、DNS 和默认网关设置。
创建后必须通过 HTTP/HTTPS 实际 bind 检查；端口失败会移除本次添加的地址，清理失败单独报告。成功后点击“保存并重启”使用。
“移除托管…”只移除注册表记录的接口 LUID、地址创建时间、前缀和 SkipAsSource 均仍匹配的地址；需要先切换正在使用的地址。
没有匹配的创建记录时拒绝移除，取消 UAC 不修改配置。权限操作在后台线程运行，编辑和保存暂时锁定。

使用系统 IP Helper API CreateUnicastIpAddressEntry / GetUnicastIpAddressEntry / DeleteUnicastIpAddressEntry，沿用既有 iphlpapi 依赖，不引入驱动或网络接管库。
该 API 创建的地址仅在当前开机/接口生命周期有效；开启随服务器启动创建后，系统重启再启动服务器时会按需重新请求授权创建。未建立后台提权任务，也没有静默改变持久网络配置。
参考：https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-createunicastipaddressentry

CI 在一次性 Windows runner 中使用实际 webserver.exe 验证创建 IPv4/IPv6、已有地址复用、真实 HTTP 响应、按所有权移除、端口冲突回滚。
日常主机的 UAC 接受/取消、系统重启和第三方网络软件兼容仍需人工验收；普通保存不会自动提权或创建地址。
